# 单源发布与 EdgeOne 单站规范

> **2026-11-26 状态更新**：GPTsite 已正式弃用，全站收口为**单仓库（`Evenstar-tools/tft-comp-notes-public`）+ 单生产部署（EdgeOne Pages · `notes.datatft.com`）**。以下历史双站同步命令仅留作归档参考，日常维护一律直接走公开仓库 PR → CI → `main` 自动部署 EdgeOne。

站主口令通过 EdgeOne Pages 环境变量 `OWNER_ACCESS_CODE`（支持 6–256 位，配防爆破限流，绝不写入公开仓库）生效；如需云端持久化草稿，再在 EdgeOne 环境变量补齐 `DATABASE_URL` 与 `DATABASE_AUTH_TOKEN`。

## 历史双站过渡说明（已归档）

本仓库是全部共享代码、赛季资料与测试的**唯一代码真源**。GPTsite 仅作为过渡期的私有站主工作区（飞书同步、云端草稿与选章发布），EdgeOne 是面向访客的正式生产站。

## 为什么不再“双份手工维护”

两站实际差异严格收敛在极薄的 **17 个平台适配文件**（认证会话、D1/LibSQL 存储、R2/Blob 媒体、构建配置与公开快照产物），其余 95%+ 的 `domain/`、`components/`、`app/`、`server/`、`data/`、`public/`、`scripts/`、`tests/` 完全共享。因此遵循以下四条原则：

1. **单一真源开发**：新功能、UI 优化与战绩数据只在一处编写（优先本仓库 `main` 分支），**禁止手工逐文件移植补丁或肉眼替换 `doxc*` / `sample-block-*` ID**。
2. **脚本自动双向同步与 ID 映射**：统一使用 `site/scripts/sync-to-public.py` 在两站间同步共享目录，自动保护平台适配壳、统一 LF 换行、按私有 `public-id-map.json` 自动完成双向 ID 重映射，并在正向导出时强制阻断私密 URL/密钥/未映射 ID 泄漏。
3. **单一自动门禁替代人肉核查**：提交前本地与 GitHub Actions 共用同一套四重门禁（`tsc --noEmit` + 全量单测 + `verify-public-release.py` 脱敏/体积/资源完整性门禁 + `next build --webpack`），合入即确保可构建、无泄漏、无死代码与重复 `gameData` 反弹。
4. **单表留痕**：跨线程交接统一只维护根目录 `改动明细.md` 的「待合批 / 已上线」状态，不再在多份交接文档里重复抄录同一笔变更。

## 日常共享代码更新（单源 3 步）

1. **在单一真源开发并跑门禁**：
   ```sh
   cd site
   npx tsc --noEmit
   node --experimental-strip-types --test tests/*.test.mjs
   python3 scripts/verify-public-release.py
   ```
2. **按需自动同步到另一站（替代手工移植补丁）**：
   - 从本仓库（公开主干）同步到 GPTsite 私有检出（自动把公开别名还原为私有 ID，且不覆盖 GPTsite 认证/D1/Worker 壳）：
     ```sh
     python3 site/scripts/sync-to-public.py \
       --source ./site \
       --target /path/to/gptsite \
       --direction public-to-gpt \
       --aliases /private/public-id-map.json \
       --dry-run
     ```
   - 确认预览无误后去掉 `--dry-run` 执行（如涉及删除共享死文件可加 `--delete`）。
   - 若某轮改动先在 GPTsite 完成，改用 `--direction gpt-to-public` 正向同步回本仓库。
3. **提 PR 合并并验证生产部署**：
   - GitHub Actions `Project checks` 自动完成类型检查、全部单测、公开站门禁与生产构建。
   - **修复 EdgeOne 自动部署**：在 GitHub App「EO Makers」权限中勾选本公开仓库后，合入 `main` 自动触发 EdgeOne 生产构建（消除人工登录控制台点补发）。

## 从 GPTsite 更新公开攻略快照

1. 站主在 GPTsite 发布管理完成选章发布，导出当前 `live` 快照至私有目录。
2. 运行快照脱敏与去重脚本（自动省略与顶层 `season` 同版本的重复 `section.gameData`，仅保留异赛季独立字典）：
   ```sh
   cd site
   python3 scripts/prepare-public-snapshot.py \
     --published /private/published.json \
     --aliases /private/public-id-map.json \
     --out data/public-preview.json
   python3 scripts/verify-public-release.py
   ```
3. 提交 `data/public-preview.json`（及新增公开素材）发起 PR，门禁全绿后合入 `main` 上线。原始快照、草稿、媒体令牌、私有 ID 映射与凭据始终留在私有工作区，绝不入库。

## 彻底退出“双站”的终态路线

本仓库已具备原生 Next.js 站主口令登录（`server/owner-session.ts`）、独立数据库适配（`server/runtime-db.ts`）与媒体存储适配（`server/runtime-media.ts`）。一旦在 EdgeOne 生产环境完成：
1. 配置站主口令、可写数据库（LibSQL/Turso）与对象存储并运行 `scripts/import-edgeone-archive.mjs` 导入全量归档；
2. 验收站主登录、飞书同步与原盘发布；

即可将 GPTsite 降级为只读归档并最终下线，全站彻底收口为**单仓库 + 单部署（EdgeOne）**，实现真正的零双份维护。
