# 单源发布与验收

公开仓库 `Evenstar-tools/tft-comp-notes-public` 的 `main` 是共享代码、攻略与战绩真源。EdgeOne 自动部署 `main` 到 [正式站](https://tftnotes.com/)。日常候选在 [本地预览](http://127.0.0.1:5173/) 验收。GPTsite 属于历史归档。

1. **开批对账。** 从最新 `origin/main` 开工，对照《改动明细》、公开 PR、已验收的本地候选、本机草稿和正式站当前原盘。按稳定攻略与棋盘 ID 记清新旧入口、搜索词和样本口径。线上站主原盘与仓库快照有差异时，先记下正式站实盘，再核对本机和候选。
2. **验收候选。** 跑适用门禁和生产构建。站主确认具体候选后提 PR，CI 对账攻略、棋盘、样本、同模型体系和采样时间。需要退役或迁移时，在 PR 正文逐项申报稳定 ID，例如 ``- retire `guide:old-slug` — 已并入新攻略``。异常项待修，已通过的项目按批次推进。
3. **发布并核对。** 发布线程合批更新 `main` 一次，确认 EdgeOne 生产部署对应本批合并提交。Makers 只为生产分支开启自动部署。正式域名生效后，用游客会话点过「全部攻略」、本版阵容搜索、顶栏搜索及受影响的旧直链。回查首页版本标记、点击后的实际构建及对应的数据采样时间。涉及原盘时，比对本批预期修改和站主保留的线上内容。 [Makers 环境管理](https://pages.edgeone.ai/zh/document/build-guide)
4. **回填结果。** 在《改动明细》原条写明候选、PR、合并提交、部署和正式站读回结果。有问题时写明受影响的入口和当前进度，修复后再补实测结果。

具体核对项目见[阵容撰写与维护全流程规范的第八章](阵容撰写与维护全流程规范.md#八提交门禁提-pr-与上线验收全流程)。在 `site/` 运行现有脚本，通过 `--guide` 传入本批攻略或变阵。数据批次加 `--data-at candidate`。脚本是目录、API 搜索、渲染和采样时间核验的一部分，客户端搜索和版本标记按手册点验。

```powershell
node scripts/verify-live-guides.mjs --origin https://tftnotes.com --guide jazz-pyke-aurora:lv8 --data-at candidate
```

站主认证与数据库凭据由 EdgeOne 配置管理。私有原始快照、草稿和 ID 映射留在私有工作区。
