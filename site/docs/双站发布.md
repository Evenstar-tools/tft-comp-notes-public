# 单源发布与验收

公开仓库 `Evenstar-tools/tft-comp-notes-public` 的 `main` 是共享代码、攻略与战绩真源。EdgeOne 自动部署 `main` 到 [正式站](https://tftnotes.com/)。GPTsite 已退役，历史配置可查 Git 记录。

1. 开批前以项目《改动明细》对照公开 PR 和本批工作树。阵容项记录攻略、棋盘短链、常用搜索词及样本状态。未就绪的项留在原条，并写明待办。
2. 用最新 `origin/main` 做基线。跑完适用门禁和生产构建后，让站主在 [本地预览](http://127.0.0.1:5173/) 验收具体候选和页面，确认后提 PR。CI 对比基线目录，拦住遗漏的攻略、棋盘、已绑定样本和同模型体系，以及同补丁旧数据覆盖。确需下线时，按门禁报出的稳定 ID 在 PR 正文逐项写明，例如 ``- retire `guide:old-slug` — 已并入新攻略``。
3. 发布线程把已确认且 CI 通过的候选合为一批，一次更新 `main`。日常预览走本地。Makers 环境管理仅让生产分支自动部署，预览环境的自动部署关闭，让 EdgeOne 每批构建一次。正式域名生效后读回。 [Makers 环境管理](https://pages.edgeone.ai/zh/document/build-guide)

   以下命令在 `site/` 运行，默认对照全量公开棋盘。`--guide` 可重复传入本批攻略或具体变阵，额外核对真实列表、搜索和渲染棋盘。数据批次加 `--data-at candidate`，用本次 checkout 的体系采样时间核对首页。

   ```sh
   node scripts/verify-live-guides.mjs --guide lifeguard-renekton:lv8-ashe --data-at candidate
   ```

4. 回填准确状态。本地待提、GitHub 已合并、EdgeOne 待生效与正式站已验收分别记录在《改动明细》原条。完成以正式站显示正确棋盘、样本和本批时间为准。

站主认证与数据库凭据由 EdgeOne 配置管理，私有原始快照、草稿和 ID 映射留在私有工作区。
