# 数据更新规范

## 触发与分工

- 版本维护人确认新补丁实装后 30 分钟内核实赛季、队列、来源补丁、构建和生效时间，更新 `data/current-patch.json`，同步版本状态。依赖新赛季或新构建的目录、映射和采样模板一并复核。阵容样本仍在积累时标「待复核」。
- 数据维护人每天按北京时间核对来源时间，刷新已核实队列的数据。普通推荐至少 100 场，均名 ≤ 4.50 进推荐，达样本门槛但均名更高进次选。跨热补滚动窗口须注明覆盖范围。
- 攻略维护人核对本批体系、公开章节和终盘棋盘，再更新文案和核心样本。首页从有效原生体系自动取至少 100 场、原始均名 ≤ 4.40 的路线。常规总量最多 12，每组最多 8，英雄强化另取最多 2。常规不足 4 套时数据门禁提示。上一榜最多保留至热补实装后 12 小时，已有有效的当前构建批次时切换。
- 少量例外写入同构建的 `data/patch-recommendations.json`。每条用 `override` 设置 `pin`（置顶）、`include`（补入）或 `exclude`（撤下）。置顶可用整数 `pinOrder`，无样本卡可设 `manualBadge`，默认显示「站主推荐」。`note` 写判断依据。过时构建的例外自动失效。
- 来源空样本、队列错配、模型换代或门禁报错时暂停发布。编排器在采集、前置门禁或归档失败时恢复本轮自动更新的快照，保留复核输出。手工编辑的候选数据按本轮 Git 差异回退至上一份已核验内容。正式服归档后若复验失败，暂停发布并核对批次清单、三件套及页面兼容快照后重试。

## 模块和入口

文件 ID 即 `--module` 的值。路径相对于 `site/`。

| 数据（`data/<id>.json`） | 刷新脚本（`scripts/`） | 默认配置 |
| --- | --- | --- |
| `hero-stats` | `prepare-hero-stats.mjs` | daily、catalog |
| `item-wearers` | `prepare-ordinary-item-stats.mjs` | daily、catalog |
| `special-item-wearers` | `prepare-special-item-stats.mjs` | daily、catalog |
| `emblem-stats` | `prepare-emblem-stats.mjs` | catalog，独立节奏 |
| `trait-stats` | `refresh-trait-stats.py` | daily、catalog，使用攻略名次表的过滤条件 |
| `guide-placement` | `refresh-guide-distributions.py` | daily、guides |
| `guide-family-stats` | `refresh-guide-families.mjs` | daily、guides，同批更新趋势 |
| `guide-carry-stats` | `refresh-guide-carries.py` | daily、guides |
| `comp-trends` | `refresh-comp-trends.mjs` | daily、guides，也可单独读取已保存体系批次 |
| `patch-recommendations` | 人工维护推荐状态、构建和公开章节引用 | daily、guides 校验 |
| `patch-recommendation-stats` | 人工维护同构建短窗核心样本 | daily、guides 校验 |

`all` 覆盖表中的全部模块。`--module` 可重复。纹章同赛季同队列保留较早补丁时提示警告。两份推荐数据保留生效前的旧构建时提示警告，当前推荐仍按构建检查。其他模块与当前赛季、队列、补丁或已声明的构建不符时拦截。

## 标准四步

在 `site/` 执行。离线检查使用 Node.js 和 Python 3。真实采集另需 Python 的 `requests`、`beautifulsoup4`，以及体系脚本使用的 Playwright 浏览器（Windows 为 Edge，其他平台为 Chromium）。

1. `npm run data:status` 查看采样时间、补丁、构建和记录数。机器读取用 `npm run --silent data:status -- --json`。攻略名次表只有日期精度。
2. `npm run data:refresh -- --profile daily --dry-run` 核对精确顺序。预览仅读本机入口并探测 Python。含体系刷新时，从当前站点的公开 `/api/guides/catalog` 导出同版目录，默认保存到 `outputs/family-review/catalog.json`，或用 `--catalog <文件>` 指定。切补丁时先将 `guide-placement.json` 的批次补丁、构建和适用 `edition` 对齐，保留独立观察的来源与时间。
3. `npm run data:refresh -- --profile daily --archive` 执行 PBE 日更和归档。仅刷新时省略 `--archive`。编排器先验收当前快照再归档，结束后复验。
4. `npm run data:verify` 核对最终候选并查看 Git 差异。门禁校验名次桶、公开引用、历史数据和补丁范围，报错时修正后重跑。

## 队列切换和历史归档

- PBE 使用 `current-patch.json` 的基础补丁和热补映射，按北京时间数据日、赛季、补丁留档。同键只接受同构建且采样时间不早于已存档批次。
- 切正式服时先核实 `sN-live`、正式补丁和生效时间。现有联网采集器面向 S19 PBE，正式服快照需另行采集并通过全站门禁。归档三件套统一标记 `S19 Ranked 19.1`（用实际赛季和补丁替换），英雄来源明确限定 `queue=1100`、赛季、补丁和滚动窗口。然后运行 `npm run data:refresh -- --archive --channel ranked --patch 19.1`。正式服按赛季、补丁留档。
- 三件套须为同队列、同补丁、同北京时间数据日及同滚动天数，采样时间须在补丁生效后。归档写入 `public/stats-history/<id>/` 的 `heroes.json`、`equipment.json`（含 `standard` 与 `special`）及 `data/stats-history.json`（零重复副本）。历史快照沿用当时的滚动窗口。
